# 🐾 Campus Paw Guardian (校园萌宠守护档案)

> **项目定位**：基于现代前端工程化与云原生 Serverless 架构的高校流浪动物智慧守护平台。

> **核心理念**：科技向善，温情赋能。打破传统校园动物管护的信息孤岛，打造可落地、可感知的智慧校园生命教育实体网络。

## 📖 项目背景与痛点 (Background)

在现代高校中，流浪动物带来了深厚的情感慰藉，但也衍生了治理难题。传统的管护模式高度依赖线下人工，存在以下五大痛点：
1. **盲目乱喂**：缺乏科学标准，高盐剩饭导致动物患病，污染环境。
2. **走失难寻**：寻找渠道零散，缺乏精准地理线索，错过黄金搜寻期。
3. **健康隐患**：伤病无报备，免疫绝育信息不透明，易引发抓咬事故。
4. **管理低效**：动协依赖 Excel 统计，数据滞后，极易形成数据孤岛。
5. **帮扶壁垒**：师生有爱心但缺乏专业知识，陷入“想帮不会帮”的困境。

本项目致力于将碎片化的校园爱心转化为数字化、科学化的保护行动，构建集“数字化建档、智能化救助、规范化管护、情感化交互”于一体的生命互助网络。

## ✨ 核心功能矩阵 (Core Features)

- **📊 萌宠数字档案大厅**：涵盖外貌特征、性格标签、栖息年限、疫苗绝育、健康状态及活动区域的全维度一宠一档。支持多维度筛选与关键字精准搜索。
- **🗺️ 校园矢量地图与足迹追踪**：自研纯前端高精度矢量平面图，摒弃第三方底图干扰。通过色阶热点圆点直观展示动物活跃度，并生成动态活动轨迹。
- **🥩 科学投喂打卡与防超载机制**：记录投喂品类与克数。内置禁忌食物知识库（如巧克力、洋葱等），并联动每日目标克数，实现超量预警与拦截，杜绝重复投喂。
- **🚨 走失求助与线索打卡网络**：全校园寻宠启事发布。师生可提供目击线索并附上精准点位与时间，系统以时间轴形式实时串联所有线索，助力萌宠回家。
- **🏠 爱心领养专区**：规范领养申请流程，结合资质问卷与动协审核，保障动物福利。

## 🧠 AI 核心赋能模块 (AI Integrations)

本项目摒弃 AI 的“装饰化”使用，将多模态大模型深度融入业务流：

1. **AI 科学投喂营养推算引擎**：结合物种、体型、年龄、生理状态（孕期/术后/患病），自动推算标准化的每日推荐克重、最佳喂食时间窗口，并生成专属禁忌清单。*(注：AI 生成的计划需流转至管理员后台审核后方可生效，确保绝对安全)*。
2. **AI 多模态健康诊断**：师生偶遇伤病动物时，可上传实拍照片与文字描述。系统调用视觉大模型进行特征提取，秒级输出病症初判（如猫鼻支、皮肤病、外伤）、严重程度分级（轻/中/紧急）及现场防抓伤急救指南。
3. **AI 拟人化萌宠讲解员**：依托 Prompt 工程为每只萌宠定制专属人设。师生可通过文字/语音与萌宠“数字分身”对话，了解其流浪故事，打破冰冷的数据壁垒。
4. **天气联动避险推演**：对接气象 API，在降雨/降温等恶劣天气下，自动匹配校园教学楼连廊、食堂后檐等避险点位，联动矢量地图引导志愿者定向巡查。

## 🛠️ 技术栈与系统架构 (Tech Stack)

采用前后端分离的现代化 BaaS 架构：

### 前端技术栈 (Frontend)
- **核心框架**: React 18 + TypeScript (保障强类型与可维护性)
- **构建工具**: Vite (极速冷启动与 HMR)
- **路由与状态**: React Router DOM v6
- **UI 与样式**: Tailwind CSS + shadcn/ui + Radix UI (定制温暖治愈系暖橙/奶油白视觉规范)
- **可视化**: Recharts (数据看板) + 自研 Canvas 矢量地图组件

### 后端与基建 (Backend & Database)
- **数据库**: Supabase (PostgreSQL 15)，具备严格的外键约束与 Check 校验。
- **安全鉴权**: Supabase Auth + **Row Level Security (RLS)** 行级安全策略，实现数据沙箱隔离。
- **无服务器计算**: Supabase Edge Functions (Deno) 承接 AI 接口调度与气象数据聚合，屏蔽前端秘钥。
- **对象存储**: Supabase Storage，对用户图片进行十六进制转码、WebP 压缩及独立存储桶管理。

## 🔬 核心技术实现亮点 (Technical Highlights)

### 1. 基于事件驱动的毫秒级寻宠广播
摒弃轮询与前端暴力查询，在 PostgreSQL 中构建 `notify_lost_pet_broadcast()` 触发器。当新走失启事发布时，数据库自动检索开启订阅的用户，直接向下派发实时站内通知，实现“一人求助，全校接力”。

### 2. 数据库底层维度的权限管控 (RLS)
告别脆弱的后端业务层鉴权，全表强制启用 RLS。通过 `auth.uid()` 唯一标识与 `SECURITY DEFINER` 鉴权函数，从数据库底层隔离用户数据，保证普通学生无法篡改他人线索，杜绝数据泄露。

### 3. 高并发下的资源轻量化处理
针对高频的图片上传操作，前端引入 `react-dropzone` 并配合定制压缩逻辑；Storage 端对图片进行自动安全编码转码，均衡画质与加载速度，大幅降低带宽成本。

## 🚀 本地开发指南 (Quick Start)

### 1. 环境准备
确保已安装 **Node.js (>= 18)** 与 **npm**。

### 2. 启动前端
```bash
# 克隆仓库
git clone https://github.com/moonlight0030/Campus-Paw-Guardian.git
cd Campus-Paw-Guardian

# 安装依赖
npm install

# 启动本地开发服务器
npm run dev
```

### 3. 配置后端服务 (Supabase)
本项目依赖 Supabase 提供云端数据服务。请在根目录新建 `.env` 文件：
```env
VITE_SUPABASE_URL=_Supabase_项目地址
VITE_SUPABASE_ANON_KEY=_Supabase_公开匿名秘钥
```
*(注：如需重建数据库，请将 `supabase/migrations/` 目录下的 SQL 文件在 Supabase 的 SQL Editor 中按序执行。)*
